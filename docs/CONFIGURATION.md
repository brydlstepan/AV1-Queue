# Configuration

What you can change: launcher settings in a `.env` file, and everything else in the app's Settings.

## Launching

Starts the server as a background process with a **system tray icon** — no console window, not shown on the taskbar. Right-click the tray icon for Open Studio / Start Queue / Pause/Resume Queue / View Log / **Open Live Log Console** / Stop Server. On first launch it opens **http://localhost:8765** in your browser automatically; if the server is already running, it just reuses it. Binds to **127.0.0.1** only. Server output goes to `logs/server.log`; **View Log** opens a static snapshot in Notepad, **Open Live Log Console** opens a console window that tails it in real time.

Or run it in the foreground with a visible console (for debugging — live log output, Ctrl+C to stop):

```powershell
.\scripts\start_queue.ps1
```

## Launcher settings

| Variable | Purpose | Default |
|---|---|---|
| `AV1QUEUE_PORT` | Server port | `8765` |
| `AV1QUEUE_HOST` | Extra addresses to bind, on top of loopback | `127.0.0.1` only |
| `AV1QUEUE_USERNAME` | HTTP Basic Auth user, for remote access | none |
| `AV1QUEUE_PASSWORD` | HTTP Basic Auth password, for remote access | none |

**Launcher settings (`.env`):** the variables below can go in a `.env` file in the project root — copy `.env.example` to `.env` and uncomment what you need (one `KEY=VALUE` per line, `#` comments). It's gitignored, so credentials stay local. Both `runGUI.bat` and `scripts\start_queue.ps1` read it at launch; restart the server after editing. A variable already set in the real environment takes precedence over the file.

**Port:** set `AV1QUEUE_PORT` (in `.env`, or as an environment variable before launching) to use a port other than 8765 (e.g. `set AV1QUEUE_PORT=9000 && runGUI.bat`, or add that `set` to a desktop shortcut's Target). Applies to both `runGUI.bat` and `scripts\start_queue.ps1`. An unset or invalid value falls back to 8765. Stop any instance already running on the old port first — the tray launcher only recognizes a server on the port it's currently configured for.

**Network access (Tailscale / LAN):** the server binds to `127.0.0.1` only by default, so it's unreachable from another machine (including over Tailscale) no matter the port — loopback never accepts remote connections. Set `AV1QUEUE_HOST` to widen that, e.g. `set AV1QUEUE_HOST=0.0.0.0 && runGUI.bat` (all interfaces) or a specific interface IP such as your Tailscale address (`100.x.x.x`, from `tailscale ip -4`). Loopback stays bound too, on top of whatever you add — so setting just your Tailscale IP gives you Tailscale + localhost **without** exposing the LAN (uvicorn's own `--host` flag can't express that combination, which is why `core/run_server.py` opens the sockets itself instead). By itself there is no login on this server — anything that can reach the bound address gets full control: adding/cancelling jobs, changing settings, replacing or clearing the stored TMDB/OpenSubtitles API keys (the server never sends saved keys back to the browser, but it still uses them). Set `AV1QUEUE_USERNAME` and `AV1QUEUE_PASSWORD` to add one (HTTP Basic Auth — your browser's native login prompt, no custom login page). It's skipped entirely for loopback requests (127.0.0.1), so the tray and a local browser tab need no credentials; it only gates the surface `AV1QUEUE_HOST` opens up, HTTP routes and the `/ws/live` WebSocket alike. Only widen the host on a network you trust; a Tailscale tailnet (which gates reachability by your own ACLs) is a reasonable case, the open internet is not — and a login is not a substitute for that judgment, just a second lock. The tray's local controls (health check, Open Studio, Start/Pause Queue) always use `127.0.0.1` regardless of either setting, since loopback keeps working once the server is listening.

## App settings

- **Output naming** — Settings → Naming templates. `[resolution]` is the output resolution (`2160p`); `[hdr]` is the HDR format of the encode (`DoVi`, `HDR10plus`, `DoVi HDR10plus`, `HLG`, `HDR10`, empty for SDR); `[note]` is an optional Edit Job suffix (e.g. `Extended`), blank when unused. Default movie template: `[name] ([year]) [imdbid-[imdbid]]/[name] ([year]) [imdbid-[imdbid]] - [[resolution]] [note]`; episodes: `[show] ([year]) [imdbid-[imdbid]]/Season [season]/[show] - S[season]E[episode] - [[resolution]] [note]` — Jellyfin's folder-per-movie / show → season layout. Add HDR with e.g. `[[resolution] [hdr]]`. (`[quality]` from older templates still works and means the same as `[resolution]`.) A `/` in a template makes subfolders under the output folder (or next to the source when none is set), e.g. `[name] ([year]) [imdbid-[imdbid]]/[name] ([year]) [imdbid-[imdbid]] - [[resolution]]` for Jellyfin's folder-per-movie layout, or `[show]/Season [season]/…` for episodes; a source already in that folder isn't nested again, and subtitle sidecars land beside the output. Changing a template renames the queued jobs too (see *Pipeline settings vs. presets*). A file without an IMDb ID (in its name, folder or `.nfo`) is looked up on TMDB when added: a movie by title / year, an episode by its **show** (TV search) — `[imdbid]`, `[year]` and `[show]` then are the series' id, first-air year and English name, never the episode's. Saving Edit Job with a new IMDb ID looks it up on TMDB in the background (needs the TMDB API key): the card's IMDb pill spins until it lands, then title, year and the output name follow the id. The queue card's resolution pill turns red when the job's preset targets a higher resolution than the source has (e.g. a 2160p preset on a 1080p file — never upscaled). The queue and history badges show the HDR format either way.
- **Presets** — Individual JSON files under `server/presets/builtin/` (git-tracked) and `server/presets/local/` (UI-created, gitignored). Each has `crf` / `preset`, an optional HandBrake NLMeans denoise (`nlmeans`: off / ultralight / light / medium / strong, with `nlmeans_tune`: none / film / grain / highmotion / animation / tape / sprite, passed as `--nlmeans=<preset> --nlmeans-tune <tune>`; off by default) plus advanced SVT overrides as `svt_params`, passed to HandBrake as `-x key=value:…` encoder options (`core/handbrake_encode.py`). Built-in presets are read-only in the UI unless **Settings → App → Enable built-in preset edits** is on. The preset editor shows a live preview of the non-default encoder options.
- **Queue** — Survives restarts via `server/queue.json`. Cancelled/failed jobs can be **Reset** back to queued.
- **Auto pause / resume** — Settings → App, two toggles (off by default), handled by `core/auto_pause.py`: **Auto-run while PC is locked** and **Auto-run while other apps are idle** (other programs' CPU below **Other apps' CPU threshold**, default 50%; this server's own process tree — HandBrakeCLI, ffmpeg, vspipe — is excluded). A running queue runs while *any* enabled condition holds and is auto-paused when none does: both on = pause only while unlocked *and* other apps are busy. Lock is checked every 5 s via the input desktop (counts as locked after 10 s, so a UAC prompt doesn't resume it); CPU pauses after a 60 s average at/above the threshold and resumes after a 2 min average below it. It never presses Start. A Pause you press is never auto-resumed; a Resume you press during an auto-pause holds until the condition clears once (e.g. lock then unlock). The Resume button reads *Resume (auto-paused)* with the reason as its tooltip; pauses and resumes are logged to the job log and `logs/server.log` (`[auto-pause]`). Turning both toggles off ends an auto-pause. Caveat: the encoder runs at above-normal priority, so while it encodes other apps get less CPU than they ask for and may read lower than on an idle PC.
- **Restart server** — The ↻ button beside Settings in the sidebar starts a replacement server process and exits the old one (it waits for the old process to release the port first). An encode running at that moment dies with the process and shows up as *Interrupted — ready to retry* once the new server loads the queue; the page reloads itself when the new server answers.
- **Pipeline settings vs. presets** — A queued job keeps only its **preset** (CRF, preset, resolution, NLMeans denoise, audio bitrates, `svt_params`) and its own picks (audio/subtitle tracks, title edits). Everything in **Settings → Pipeline** (SSIMU2 mode / post-encode score, autocrop, container, audio format/languages, subtitle options) and **Test mode** (toggle + range) is stored on the server (`pipeline` in `server/settings.json`), stamped onto queued jobs when you save it (their cards update), and **re-read when each job starts** — so changing them after adding files still applies, from any browser. The same goes for the naming templates / auto-name, the online subtitle search and Preserve Dolby Vision RPU. Audio / subtitle track picks follow new languages / kinds unless you changed a job's picks by hand. The job log notes anything that changed at start. A job's output name follows the container / Test Mode / template it actually runs with. A running encode keeps what it started with; lp / low-memory are read as each job starts.
- **Test mode** — Global toggle + duration settings in the UI; jobs run a short trim instead of the full file (see above: read at job start, not frozen when the job was added). The output is named after the job's preset (`<name>.test_FHD (noise).mp4`), so encodes of the same segment with different presets sit side by side; a job without a preset falls back to the time range (`.test_003540-003600`). Re-running the same preset adds `_2`, `_3`, …
- **Audio defaults** — With no explicit selection, a job takes the best track per preferred language (Settings → Audio, English by default; best = surround first, then channel count, then bitrate), or the single best track overall if none match. An explicit empty selection in the job editor means video-only.
- **HDR** — See [Format philosophy → HDR & Dolby Vision](ARCHITECTURE.md#hdr--dolby-vision).
